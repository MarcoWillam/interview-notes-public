# 伯乐 AI · 面试评估工作台

Chrome 网页应用：上传或粘贴简历、导入 `.md` / `.txt` 面试记录、选择岗位标准，生成有原文引用的辅助评估，由面试官确认最终意见。

网页服务与分析电脑现已分离：网页提交任务 → 服务器持久排队 → 已配对电脑主动领取 → 本机 Codex 分析 → 结果回传。使用电脑上现有的 ChatGPT 登录，模型分析仍需联网并消耗该账号额度。服务器不需要安装 Codex，也不持有 Codex 登录凭据。

## 本地预览

使用 Node.js 24+，安装 Codex CLI 并用 ChatGPT 登录（验证版本 0.153.4）。

```sh
npm ci
codex login
npm run build:server
npm start
```

打开 http://localhost:8787/。`npm start` 启动本地队列服务器和独立连接器，自动配对本机，免网页登录。原有浏览器面试记录和模板继续保留。退出服务会停止连接器；排队任务仍在磁盘，正在执行的任务会在租约到期后标记失败。

页面顶部提供“电脑连接”和全局“任务中心”。离线时也能提交，电脑恢复连接后领取。任务中心显示当前账号的运行、等待和暂停数量、排队位置、等待或执行时长；简历阅读标注“准备优先”。关闭网页不会取消已提交的任务；再次打开后仍可控制任务或查看结果。当前页保持打开时，完成的报告会自动填入当前面试；任务中心查看历史结果不会覆盖正在编辑的另一场面试。

## 面试流程

1. 上传 .doc、.docx 或文字版 .pdf 简历（最多 5 MB，PDF 最多 30 页），也可粘贴正文，最多 30,000 字符。附件由浏览器 Worker 提取，原文件不上传。扫描件、加密/损坏文件或无文字页面会提示转换或手动粘贴；失败保留原文。
2. 生成前确认岗位；AI 产品经理还必须选择有无笔试。内置 AI 产品经理和产品运营使用 V2 提纲：5 道必问题、最多 3 道候选题，必问预计不超过 32 分钟；主问题为 8–24 个字符且只问一个核心点，并按岗位八维显示能力覆盖。AI 研发、自定义模板和历史记录继续使用兼容的六题提纲。每份记录成功生成后锁定简历和本场标准；失败、暂停或停止时仍可重试。
3. 主提纲生成后，可以在提纲底部输入一个维度或关注点生成“补充追问”。Codex 会同时参考本场岗位要求、简历阅读结果、原主提纲和已生成的补充组，固定返回 2 道简短问题；结果按组追加，不修改原提纲。每组可以单独删除，也可以从版本历史恢复。
4. AI 产品经理有笔试时，第 2–4 道必问题按统一笔试考量维度复盘；有 ZIP 作品时优先逐字引用本地作品文件。最初选择“无笔试”后补笔试或作品，会保留 5 道必问题，用 3 道复盘题更新候选区，并归档此前候选题供回看。
5. 在豆包完成录音转写，将对话整理为 UTF-8 `.md` 或 `.txt` 文件，也可直接粘贴文本；最多 1 MiB、80,000 字符。
6. 导入后按纯文本编辑；明确面试官和候选人归属，核对后勾选确认。替换已有正文需确认；文件错误保留原文。不执行 Markdown 内的 HTML。
7. 使用全局岗位模板，按需调整本场标准，再生成辅助评估。提交时简历、标准、对话文字会经过工作台服务器，由配对电脑发送给 OpenAI。
8. 核实引用和判断，填写人工结论并导出 Markdown。简历自述不视为已验证证据，没有对话证据的维度不评分，不自动决定录用。

页面不申请麦克风，不转写音频；Word/PDF 仅用于简历，面试过程使用 `.md`、`.txt` 或粘贴文本。旧音频代码仅为历史兼容保留，历史音频仍可下载。

## 复试流程

“新建面试”可选择“新建初试”或“新建复试”。复试创建分三步完成：导入初试记录、补充简历、确认候选人与岗位。初试记录支持 UTF-8 `.md`、`.txt` 或直接粘贴；伯乐 AI 导出的 `# 面试评估记录` 会自动识别候选人、岗位和其中的简历正文，无需重复上传简历。其他来源的初试记录必须另行上传 `.doc`、`.docx` 或文字版 `.pdf` 简历，附件仍只在浏览器提取文字。

确认后，Codex 会根据初试已经问过的内容、仍缺失或矛盾的证据、候选人简历和当前岗位标准，生成 6 道必问题及最多 3 道候选题，建议时长 45–60 分钟。复试问题不会原样重复初试；需要继续核实同一经历时，会改为判断、取舍、失败复盘或迁移能力等更深角度，并显示与初试问题的差异说明。

复试结论是一份独立报告。能力评分和证据只允许引用本轮复试记录；初试材料仅用于准备问题，并在报告中以“复试已验证 / 复试提供补充 / 与初试存在冲突 / 本轮仍未验证”四种状态单独对照。系统不会合并初复试分数，也不会自动生成最终录用决定。复试记录与初试记录一样只对创建它的账号可见，并在左侧记录、候选人看板和当前状态条显示“复试”标识。

## 保存与全局偏好

面试草稿、完整记录、人工意见和岗位模板先保存在当前浏览器 IndexedDB，部署版再按网页登录账号同步到服务器。补充追问分组和进行中的任务编号也随本人记录保存；刷新、换电脑或短暂断网后，可以恢复记录和继续查看同一任务。本机预览只保存到本地数据库。新面试复制全局默认标准，修改全局不会覆盖历史快照。

浏览器 IndexedDB 是离线副本；清除站点数据、无痕退出、换网址会移除这份本地副本，联网登录后可重新拉取已同步记录。尚未同步的本地修改仍需先恢复联网或导出保存。多标签同一账号只允许一个工作台写入。

服务器 SQLite 另存账号、配对电脑和评估任务：

- 离线任务最多等待 24 小时，每个账号最多 20 个待处理任务。
- 相同账号、类型、名称和输入的活动任务会沿用原任务；保留期内已完成的相同简历阅读与笔试复盘补充也会直接复用结果，避免页面关闭后重复消耗额度。连接器优先领取简历阅读和笔试复盘补充，再领取结论评估。
- 等待或运行中的任务可以暂停。暂停保留材料；恢复会重新排队并从头执行，暂停前已经消耗的 Codex 用量不会退回。
- 停止任务会立即清除服务器上的简历、标准与对话原文，不能恢复。任务完成、失败或停止后也会逻辑清除输入；结果中的引用仍属于报告。
- 结果和终止任务记录保留 7 天，清理在服务运行时执行；请及时下载报告。数据库备份需遵守自己的保留策略，逻辑删除不等于物理擦除历史磁盘或备份。
- 每台连接器一次领取一个任务。新版连接器执行中每 5 秒心跳，租约 60 秒；暂停或停止运行任务后通常会在下一次心跳中断本地 Codex。补充追问作为“准备优先”任务进入任务中心，支持暂停、恢复、停止及完成结果预览。
- 补充追问和复试任务要求协议 5。协议 5 的生成规则和结构由服务器下发；已有协议 5 连接器可直接领取复试提纲和复试评估任务，因此本次网页和服务端更新后无需替换连接器或重新配对。

## 部署服务器、连接自己的电脑

完整步骤见 [部署说明](docs/deployment.md)。服务器只运行 Node + SQLite + 静态网页，放在 HTTPS 反向代理后；电脑向服务器发起出站请求，不需要开放电脑端口。

服务器构建后，配置独立数据目录、公开地址和首次管理员账号，运行 `npm run start:server`。首次创建账号后可移除环境中的初始密码。默认只初始化一个管理员账号，无公开注册入口。`npm start` 是本机免登录预览，不能作为正式启动命令；正式服务拒绝使用预览数据库。

登录网页，在“电脑连接”下载并解压不含凭据的专用连接器包，生成一次性配对码，然后在解压后的 `interview-connector` 目录运行：

```sh
npm run connector -- --server https://your-workspace.example --pair 网页上的配对码
```

如果终端提示符仍是 `~ %`，或 npm 报错找不到 `/Users/用户名/package.json`，说明命令是在用户主目录执行。先执行 `cd ~/Downloads/interview-connector`；确认当前目录包含 `package.json` 后重新运行配对命令。若浏览器把解压目录改了名字，请用实际路径。配对码超过 10 分钟时需在网页重新生成。

配对成功后，连接器凭据存于本机 `.local/connector.json`（仅当前用户可读写，已被 Git 忽略）。之后只需 `npm run connector`，保持运行即可。配对码有效 10 分钟且只能使用一次，重新生成会替换旧码；网页可以解除电脑配对。Codex 自身的认证由 CLI 管理，不复制到连接器文件或服务器。

协议 5 连接器由服务器下发提示词和输出结构。本次从旧版升级时，在原连接器目录替换程序文件并保留 `.local/connector.json` 与 `works`，无需重新配对；完成后，岗位模板、提纲和评估规则更新无需再次替换连接器。

macOS 连接器会依次检查终端中的 `codex`、ChatGPT 应用内置 CLI 和 Codex 应用内置 CLI。也可设置 `INTERVIEW_CODEX_BIN` 为 CLI 的绝对路径；显式路径优先。连接器仅接受 HTTPS 网站根地址，本机调试允许 HTTP loopback；禁止带凭据 URL 和跨站重定向。

## 分析约束与兼容入口

连接器通过 `codex exec` 的 stdin 传入材料，使用只读沙箱、临时空目录和结构化输出，禁用外部工具入口，忽略用户配置及项目规则；认证限定 ChatGPT，不回退到 API key。每场最长约四分钟。服务器收到报告后再次校验维度、评分和逐字引用，非法报告标记失败，原始模型报错不展示给网页。

旧的直接分析模式可用 `npm run build` 后 `npm run start:local` 启动，仅供本机兼容；此模式关闭网页会停止分析。旧兼容 API 适配器用 `.env` 的 `ANALYSIS_BASE_URL`、`ANALYSIS_API_KEY`、`ANALYSIS_MODEL`，通过 `npm run start:api` 启动。两者不包含服务器账号和队列能力，不用于本次远程部署。旧 ASR 密钥不用于评估。

`npm run dev` 仍为原 Vinext 页面开发入口；队列版修改后使用 `npm run build:server` 重建并刷新网页。`npm run build` 同时构建原 Vinext 与新增静态入口。
