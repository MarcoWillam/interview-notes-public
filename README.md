# 伯乐 AI · 面试评估工作台

> 上传 / 粘贴简历、导入面试记录、选定岗位标准，由**本机 Codex** 生成带逐字原文引用的辅助评估，最终结论由面试官确认。MIT 开源。

## 特性

- **引用可追溯**：每条评估结论都附带面试记录中的逐字引用；未经验证的简历自述不视为证据，没有对话证据的维度不评分。
- **本机分析、零凭据托管**：网页提交任务 → 服务器持久排队 → 已配对电脑主动领取 → 本机 Codex 分析 → 结果回传。服务器不持有任何模型凭据，复用你电脑上已有的 ChatGPT 登录。
- **岗位化提纲**：内置 AI 产品经理 / 产品运营 V2 提纲（5 必问 + 最多 3 候补，八维能力覆盖）；AI 研发、自定义模板、历史记录使用兼容六题提纲。
- **补充追问**：在主提纲基础上按维度生成 2 道短追问，按组追加、可单独删除或版本回滚。
- **离线可用**：断网也能提交，电脑恢复连接后自动领取；浏览器 IndexedDB 本地草稿 + 服务端账号同步。
- **任务可控**：暂停 / 恢复 / 停止，租约心跳、去重复用、优先级调度。
- **自托管友好**：单 Node 进程 + SQLite + 静态网页，置于 HTTPS 反向代理后即可自用。

## 架构

```
┌────────────┐   提交任务    ┌──────────────────┐   领取任务    ┌─────────────────┐
│  网页工作台 │ ───────────▶ │    队列服务器       │ ◀─────────── │    分析电脑        │
│ (Next.js)  │              │  (Node + SQLite)   │              │   (Codex CLI)    │
└────────────┘              └──────────────────┘              └─────────────────┘
       ▲                           │ 持久排队                          │ 只读沙箱执行
       │                           ▼                                  ▼
       │                     结果回传 / 引用校验                  stdin 传入材料
  浏览器本地草稿 (IndexedDB)
```

服务器仅做排队与结果校验，不调用模型；模型分析在本机 Codex 的只读沙箱中完成，每场最长约 4 分钟。

## 技术栈

- 前端：Next.js 25 · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui
- 服务端：Node.js 24 · SQLite · 持久任务队列
- 分析：本机 Codex CLI（ChatGPT 登录），只读沙箱 + 受限 MCP 工具
- 解析：PDF.js（中文简历）· Mammoth（Word）
- 部署：单机构建，可选 Cloudflare Workers

## 本地预览

要求 Node.js 24+，并安装 Codex CLI 且已用 ChatGPT 登录（验证版本 0.153.4）。

```sh
npm ci
codex login
npm run build:server
npm start
```

打开 http://localhost:8787/。`npm start` 启动本地队列服务器与独立连接器，自动配对本机、免网页登录；退出服务即停止连接器，排队任务仍存于磁盘。

> **注意**：`npm start` 仅用于本机免登录预览，**不能**作为正式启动命令。正式服务请用 `npm run start:server`（见下文）。

## 自托管部署

完整步骤见 [部署说明](docs/deployment.md)。要点：

1. 服务器只运行 Node + SQLite + 静态网页，置于 HTTPS 反向代理后；电脑向服务器发起出站请求，**无需开放电脑端口**。
2. 配置独立数据目录、公开地址与首次管理员账号，运行 `npm run start:server`；默认仅一个管理员账号、无公开注册。
3. 在网页「电脑连接」下载不含凭据的连接器包，生成一次性配对码，于解压目录运行：

   ```sh
   npm run connector -- --server https://your-workspace.example --pair 配对码
   ```

4. 配对成功后凭据存于本机 `.local/connector.json`（已被 Git 忽略）；之后只需 `npm run connector` 保持运行。

## 面试流程

1. **简历**：上传 .doc / .docx 或文字版 .pdf（≤ 5 MB，PDF ≤ 30 页），或粘贴正文（≤ 30,000 字符）；附件在浏览器 Worker 内提取，原文件不上传。
2. **岗位与提纲**：生成前确认岗位；AI 产品经理还需选择有无笔试。V2 提纲 5 必问 + 最多 3 候补，必问预计 ≤ 32 分钟。
3. **补充追问**：提纲底部按维度生成，固定 2 道短问，按组追加、可单独删除或版本回滚。
4. **面试记录**：在豆包完成转写后整理为 UTF-8 `.md` / `.txt`（≤ 1 MiB / 80,000 字符），也可直接粘贴；导入后按纯文本编辑并核对归属。
5. **评估**：选岗位模板、调标准后生成辅助评估；提交材料经服务器转发给配对电脑上的 Codex。
6. **人工结论**：核实引用与判断，填写人工结论并导出 Markdown。不自动决定录用。

页面不申请麦克风、不转写音频；Word / PDF 仅用于简历，面试过程用 `.md` / `.txt` / 粘贴文本。

## 保存与任务策略

- 草稿先存浏览器 IndexedDB，部署版按账号同步到服务端；刷新 / 换机 / 断网后可恢复。
- 离线任务最多等待 24 小时，每账号最多 20 个待处理任务；相同输入的活动任务会复用结果，避免重复消耗额度。
- 任务可暂停（保留材料，恢复后重排从头执行）/ 停止（立即清除服务器上的简历、标准与对话原文，不可恢复）。
- 结果与终止记录保留 7 天，请及时下载；逻辑删除不等于物理擦除历史磁盘或备份。
