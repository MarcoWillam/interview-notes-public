# 伯乐 AI：面试材料评估工作台

2026-09-09。当前交付为云端网页 + 用户已配对电脑的本地 Codex，部署地址 https://your-server-ip。简历支持附件提取或粘贴文本，面试过程限定 `.md`。

## 范围与流程

Chrome 工作台保留三个页签：候选人简历、面试记录、结论评估。当前面试标题下方持续显示候选人、岗位、笔试情况（仅支持该状态的岗位）与提纲状态；“面试设置”弹窗负责编辑候选人、岗位模板与本场标准，不再常驻右侧栏。岗位要求、评估维度等固定标准默认收起，每次打开设置时按需展开。模板下拉持续显示当前模板；本场手工调整、来源模板被删除或来源模板后来更新时显示对应状态，不覆盖本场快照。页面始终使用单列主工作区；650px 以下状态、导航与操作换行，弹窗可独立滚动。简历直接粘贴，最大 30,000 字符。录音和转写由用户在豆包完成，工作台仅导入 UTF-8 `.md`（大小写扩展名均支持），最大 1 MiB / 80,000 字符。无 OCR、现场录音或语音配置入口；Word/PDF 仅用于简历导入。

工作台顶部使用一行全局导航，集中显示品牌、本机保存状态、电脑连接、任务中心、全局设置和当前账号；窄屏将三个工具操作收进“更多操作”，账号操作保留在用户名菜单。左侧本地面试列表默认按添加时间倒序，可切换为正序或自定义排序。自定义模式支持拖动手柄与上下方向键，顺序和当前排序方式按网页登录账号保存在当前浏览器；新记录插入自定义顺序顶部。记录的添加时间在创建后保持不变，旧记录没有该字段时以原更新时间兼容显示。

面试记录上传后按纯文本预览编辑，保留发言标签、时间戳和 Markdown 内容，不执行其中 HTML。文件空白、编码错误、二进制、超限或读取失败时保留原数据。重新上传已有正文需确认替换；成功导入才清除旧评估、人工确认及校对确认。人工意见保留供核对。编辑内容后需重新确认。

选择岗位模板，校对说话人和文本后，按岗位要求、维度、简历背景与面试对话生成评估。输出维度说明、原文证据、无证据标记和待核实问题。最终意见由面试官填写确认，支持导出 Markdown。本地 Codex 未登录时显示真实状态，不模拟报告。

## 数据与服务

自动保存当前浏览器 IndexedDB，文件正文与来源名保存，原上传文件不额外保存。刷新恢复最近面试，支持历史切换与删除。全球默认标准与本场快照规则沿用现有实现；不改动历史面试。旧录音保留历史下载入口，主页不加载录音模块。

本地分析由连接器调用 Codex CLI（旧直接模式使用 Node 网关），沿用本机 ChatGPT 登录，无需 API 密钥。附件成功提取后自动提交简历阅读；粘贴或编辑正文后由用户点击阅读，面试评估由用户主动生成。提交的材料会经本地 Codex 发送给 OpenAI，限定只读沙箱和无外部工具的临时运行，忽略用户配置，结构化输出。旧 `/chat/completions` 适配器另行保留，非本地默认路径。引用须匹配面试正文，证据不足不可评分，简历不得当成已验证面试证据；不自动决定录用。

## 验收

测试文件类型、大小、UTF-8、BOM/换行、二进制、80,000 字符边界、读取错误、材料本地保存与恢复、旧数据兼容及服务验证。类型、lint、构建通过，localhost:8787 返回正常页面。发布前完成完整测试、类型检查、lint、构建及发布包校验；生产 HTTPS、会话安全与真实 Codex 简历阅读以虚构样例验证，不自动读取历史面试。

## 服务器网页与本地电脑（当前默认模式）

用户已批准并部署远程网页 + 本地 Codex 连接器。新增独立静态入口与 Node 24/SQLite 服务。生产模式使用账号会话；本机预览免登录并自动启动一个独立连接器，预览数据库与正式数据库分开。

浏览器提交材料生成持久任务，电脑持可撤销令牌主动领取自己账号的任务，沿用本机 Codex ChatGPT 登录，回传结果。一次性配对码 10 分钟有效，设备令牌只用于工作接口。浏览器不接触 Codex 凭据，服务器也不保存此凭据。

任务状态：queued → running → completed / failed / cancelled。每台电脑单次领取，60 秒租约，10 秒心跳；中断不自动重复消耗额度。关闭网页只停止观察，明确取消才取消任务。顶部任务列表可在重新打开后查进度、查看和下载报告，不覆盖其他本地面试。队列等待最多 24 小时，终态清除输入，报告与任务保留 7 天。

完整面试草稿、人工意见与全局模板仍保存在浏览器，生产账号之间使用不同 IndexedDB；本机预览保留旧数据。提交任务所需输入和结果另存服务器。结果仍按原文与维度校验，最终意见由面试官确认。

正式服务支持多个独立面试官账号，但不提供公开注册或共享记录。`owner` 是唯一的简易管理账号，可在登录后的顶部“账号配置”中只填写账号名和初始密码来创建面试官；服务端再次校验 owner 会话并安全哈希密码。服务器命令行继续支持新增、列出、重置密码、停用和启用。每个账号只能访问自己的任务，并需在自己的电脑上单独配对本地 Codex。停用账号立即注销全部网页登录、作废配对码和连接器、终止并清除未完成任务输入；重新启用后保留原密码，但需重新登录和配对。重置密码同样作废已有登录和连接器，保留尚未领取的排队任务。

远程模式支持离线排队，无在线电脑时不禁用生成按钮。状态仅反映设备心跳及 Codex 登录检查，运行时错误（网络、额度、结构）仍会终止任务并展示通用原因。部署要求与数据保留见 `docs/deployment.md`。旧的直接 Node 网关通过 `start:local` 保留，非当前默认。

## 简历附件与阅读

支持 DOC/DOCX 和文字版 PDF（5 MB，PDF 30 页，提取后 30,000 字），在浏览器后台自动提取。原附件只在浏览器提取、不上传；提取文字与完整岗位标准会发送到用户已配对电脑的本地 Codex，经队列服务器短期中转。浏览器保留正文和文件名，服务器按上述任务保留策略处理输入与结果；“原附件不上传”不代表提取文字不会离开浏览器。

成功提取后自动提交 kind=resume 的 Codex 阅读任务，不需要面试对话，也不再要求先勾选正文确认。AI 产品经理在提交阅读前必须明确选择本场“有笔试”或“无笔试”；尚未选择时，上传后的自动阅读和手动阅读都会先弹出确认，选择后直接继续同一次阅读流程。已有正文时先确认替换；取消、提取失败均保留原正文。粘贴或编辑后通过“用 Codex 阅读简历”或“重新阅读简历”提交，不因每次按键重复运行。导入完成、新建面试和打开历史记录时正文默认折叠，展示文件名和字符数，可展开检查、编辑；附件解析异常时自动展开以便人工修正。编辑正文或岗位标准会清除旧阅读和评估结果，人工意见保留。

结果优先展示色差明确的面试提纲，简历摘要、教育背景、工作经历、项目经验、技能和其他建议追问收进默认关闭的“简历阅读结果”。提纲包含恰好六道不同的结构化行为问题，建议 30–40 分钟；每题包含来源标签、模板内 1–2 个维度、提问原因、原文依据（无依据为 null）、1–3 个观察点与 1–2 个追问。观察点与追问默认折叠。自驱力必须覆盖，AI 产品经理提纲还围绕 AI 理解与产品化判断。简历均为候选人自述，尚未面试核实。

姓名仅在简历明确写出且证据为包含该姓名的连续原文时采纳；无有效证据则不填写。当前候选人为空时自动填入，姓名一致时保留；冲突弹窗默认聚焦“保留当前姓名”，只有明确选择才使用简历姓名，关闭/取消同样保留当前值。采纳不同姓名清除旧评估及人工确认，保留姓名则保留这些状态，不重新调用 Codex。

来源文件名、正文与阅读结果保存在本地历史；旧校对字段保持兼容，不成为新流程门槛。任务列表可找回和下载阅读报告，旧版没有六题的阅读仍可展示。旧队列行默认为 interview，旧连接器只领取 interview，避免把简历误当面试评估。两类任务沿用同样的隔离、租约、取消、重试及保留规则。

## 内置校招模板

新库及旧库升级时提供“AI 产品经理（校招）”和“产品运营（校招）”两个内置模板，不自动选定默认模板、不覆盖已有模板或历史面试快照；用户可编辑、删除，普通重开不会恢复已删除模板。每个模板均有岗位要求、八个评估维度、重点、评分说明与报告要求，评分说明自身包含行为评分锚点及自驱力判定依据；选择后把完整标准带入本场快照。

AI 产品经理考察用户洞察与问题定义、产品方案与范围取舍、AI 理解与产品化判断、数据验证与迭代意识、自驱力与结果闭环、学习力、挑战力与韧性、团队精神与沟通协作。该模板在简历阅读前的弹窗中只提供“有笔试 / 无笔试”二选一，当前面试状态条显示待确认或已选择的状态；状态随本场记录保存，不录入具体题目或答卷。有笔试时，六题提纲中的第 2–4 题按既有考量框架生成笔试复盘题，覆盖问题定义、用户理解、范围取舍、AI 核心价值、人与 AI 责任、用户控制、失败降级和验证假设；无笔试时不得出现笔试措辞。该选项不应用于产品运营或其他模板。旧记录已经生成提纲或原先勾选有笔试时按已确认处理，避免升级后无故要求重读。

产品运营以用户运营约 60% / 数据增长约 40% 组织提问和结论，不机械计算总分，考察用户理解与用户分层、用户生命周期与关系运营、运营策略与落地执行、数据分析与增长实验，以及两岗共有的自驱力与结果闭环、学习力、挑战力与韧性、团队精神与沟通协作。AI 产品经理和产品运营的结论评估均先展示上述四项“通用素质能力”，再展示四项“产品能力”或“运营能力”；总评依次使用通用素质、岗位专业能力和综合判断三段，其中自驱力是通用素质的重点。页面、任务中心和 Markdown 导出使用相同顺序。完整匹配两个内置八维模板的历史结果自动按组展示，不重新调用 Codex；AI 研发、自定义和不完整历史维度保持原顺序。模板和 Codex 均不自动作出录用或淘汰决定。
